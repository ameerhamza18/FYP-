SECTION 1: PROJECT ABSTRACT / BRIEF
================================================================================

TrustLayer is an AI-powered, multi-layered cybersecurity platform designed to
detect and explain scam messages, phishing attempts, and social-engineering
attacks targeting everyday users in Pakistan and globally.

PROBLEM STATEMENT:
------------------
People daily receive suspicious SMS messages, WhatsApp texts, emails, URLs,
screenshots, fake job offers, investment fraud, fake banking messages, prize
scams, and impersonation attempts. Existing solutions provide only a binary
Scam / Not Scam verdict, which is useless for building genuine digital
resilience and awareness among non-technical users.

SOLUTION:
---------
TrustLayer goes far beyond a simple binary verdict. Instead of just saying
Scam, it answers:

    HIGH RISK -- 91/100
    Threat Type   : Phishing / Financial Fraud
    Why           : Suspicious URL, urgency-based social engineering,
                    credential request, financial impersonation
    What To Do    : Do not click links. Do not share OTP or passwords.
                    Report to PTA (9000) and your bank fraud line.

The platform intercepts threats BEFORE they cause harm, provides a full
explainable breakdown of WHY something is risky, and gives the user clear,
actionable safety recommendations.

WHAT TRUSTLAYER DETECTS:
------------------------
1. Phishing           -- urgency, impersonation, suspicious URLs, credential harvesting
2. Fake Job Scams     -- upfront payment requests, unrealistic salary, work-from-home fraud
3. Banking Scams      -- financial impersonation, account blocking threats, OTP/PIN harvesting
4. Investment Scams   -- guaranteed profit claims, Ponzi schemes, unrealistic return promises
5. Prize / Lottery    -- lucky draw baits, BISP/government grant impersonation, prize lures
6. Impersonation      -- FBR, NADRA, Police, HBL, UBL, Meezan Bank, Telenor

SOCIAL ENGINEERING TECHNIQUE DETECTION (8 Techniques):
-------------------------------------------------------
  - Authority          : I am calling from your bank / FBR / Police
  - Urgency            : Act within 10 minutes / Abhi verify karein
  - Fear               : Your account will be blocked / ho jayega
  - Reward             : You have won Rs. 50,000 / Inam jeet liya
  - Scarcity           : Only 2 spots remaining / Limited offer
  - Trust/Impersonation: Official app / Verified link / Dear Customer
  - Financial Pressure : Pay registration fee / Send on JazzCash
  - Credential Harvest : Enter your OTP / PIN share karein

KEY DESIGN DECISIONS:
---------------------
1. The AI/LLM is NOT the security decision-maker. Risk scores are produced by a
   deterministic, auditable fusion engine combining:
     - ML Classifier (TF-IDF + Logistic Regression, 30% weight)
     - Rule Engine   (14+ expert security rules, 35% weight)
     - Threat Intel  (known-bad domain/keyword feed, 20% weight)
     - URL Analyzer  (static URL risk analysis, 15% weight)

2. The LLM ONLY generates the human-readable explanation AFTER the verdict is
   already decided. This prevents prompt-injection attacks and hallucinated scores.

3. All analysis is privacy-preserving:
     - Screenshots are processed in-memory -- never written to disk
     - Submitted URLs are analyzed statically -- server never fetches them
     - Content stored as truncated, sanitized snippets + SHA-256 hash only

RESEARCH QUESTIONS (FYP):
--------------------------
  RQ1: Can the system classify scam messages with high precision and recall?
  RQ2: Can it identify psychological manipulation techniques used by scammers?
  RQ3: How effective are the security controls against real-world attacks?
  RQ4: What is the system latency and throughput under load?

EVALUATION METRICS:
-------------------
  Precision / Recall / F1-Score / ROC-AUC / FPR / FNR / Latency / Throughput

TARGET USERS:
-------------
  - General public (mobile app -- non-technical users)
  - Security analysts and SOC teams (web admin dashboard)
  - Banks, telecoms, government agencies (API integration)

REGIONAL COVERAGE:
------------------
  - English messages (primary)
  - Roman Urdu messages (EasyPaisa, JazzCash, BISP, banking scams)
  - URLs (phishing domains, typosquatting, shorteners, IP-literal hosts)
  - Screenshots (OCR-based text extraction + analysis)

MIGRATION TOOL  : Alembic
ACTUAL DB FILE  : trustlayer/backend/trustlayer.db (106 KB, live dev data)

DATABASE SCHEMA -- 6 TABLES:
------------------------------

  1. users
       id, email (unique), password_hash (bcrypt), role (user|admin),
       is_active, created_at, last_login_at

  2. analyses  [CORE TABLE -- one row per scan]
       id, user_id (FK), input_type (text|url|screenshot),
       content_hash (SHA-256), content_snippet (sanitized),
       risk_score (0-100), risk_level (LOW|MEDIUM|HIGH|CRITICAL),
       threat_type, ml_score, rule_score, intel_score, url_score,
       recommendation, explanation, engine_breakdown (JSON),
       campaign_signature (SHA-256 hash), campaign_flagged,
       latency_ms, created_at

  3. indicators
       id, analysis_id (FK), category, severity, title, detail

  4. se_findings
       id, analysis_id (FK), technique, intensity (LOW|MEDIUM|HIGH), evidence

  5. campaigns
       id, signature (SHA-256 unique), hits, distinct_users, severity,
       sample_snippet, first_seen, last_seen

  6. audit_logs  [APPEND-ONLY]
       id, user_id (nullable), action, resource, ip, user_agent, meta (JSON),
       created_at

TABLE RELATIONSHIPS:
--------------------
  users ---< analyses ---< indicators
                  |
                  +------< se_findings
  campaigns  <-- correlated from analyses.campaign_signature
  audit_logs <-- every auth + analysis event

MIGRATION COMMANDS:

  alembic revision --autogenerate -m "add_column_name"    # New migration
  alembic downgrade -1                                     # Rollback one version

----------------
  python -m ml.training.generate_dataset
  python -m ml.training.train_model

RUN ALL TESTS:
---------------
  pytest tests/ -v
  # Expected: 85 passed

-----------------------------------
  cp backend/.env.example backend/.env   # Fill in SECRET_KEY, ADMIN_PASSWORD
  docker compose -f infrastructure/docker/docker-compose.yml up --build
  # API: http://localhost:8001
